<Note label="in numbers">
An A100 reads 2 TB/s. A 32 GB cache is 16 ms per token spent before any arithmetic
happens.
</Note>

At batch size 1 an autoregressive step performs a handful of matrix–vector products
and re-reads the entire KV cache. Arithmetic intensity is therefore near 1, and the
step time is a division: bytes read over memory bandwidth.

<Eq caption="eq. 1 — L layers, batch b, h_kv key/value heads" lead>

$$
\text{bytes}_{KV} = 2 \cdot L \cdot n \cdot h_{kv} \cdot d_{\text{head}} \cdot b
\cdot \text{sizeof(dtype)}
$$

</Eq>

MQA sets $h_{kv} = 1$; grouped-query attention interpolates, sharing one K/V head
per group of $g$ query heads. GQA at $g = 8$ recovers essentially all of
multi-head quality at an eighth of the cache, which is why it, rather than MQA, is
what shipped.

<Eq caption="eq. 2">

$$
\underbrace{h_{kv} = h}_{\text{MHA}}
\qquad
\underbrace{h_{kv} = h/g}_{\text{GQA}}
\qquad
\underbrace{h_{kv} = 1}_{\text{MQA}}
$$

</Eq>

<Rule label="Implementation" />

<CodeFrame meta="python · torch ≥ 2.1">

```python
import torch
from torch import Tensor
import torch.nn.functional as F


def gqa(q: Tensor, k: Tensor, v: Tensor, mask=None) -> Tensor:
    """q: [B, H, N, D]   k, v: [B, H_kv, M, D]   H % H_kv == 0"""
    h, h_kv = q.size(1), k.size(1)
    if h != h_kv:
        repeat = h // h_kv
        k = k.repeat_interleave(repeat, dim=1)
        v = v.repeat_interleave(repeat, dim=1)
    return F.scaled_dot_product_attention(q, k, v, attn_mask=mask)
```

</CodeFrame>

`repeat_interleave` here is expository — it materialises the expansion. In a real
kernel the grouping is expressed as a stride of zero over the head dimension, so
the shared K/V head is read once and broadcast, which is the entire point of the
technique.
